# Pre-publication review

## 2.1.1 Cursor model display — 2026-10-06

The Cursor summary previously used the smallest percentage across Included, Cursor models and Other models. The front card now selects the validated autoPercentUsed window explicitly, and compact/tray/taskbar displays share that selection. If the Cursor-model window is missing or expired, the summary is unknown rather than another category. All reported windows remain intact for details, per-window forecasts/alerts and history; their actual limiting allowance is unchanged. No provider request, credential reuse, cache format, sampling, dependency or privacy behavior changes.

Added native regressions with different category percentages, known zero/full, missing/expired primary quota, stale readings, full/compact accessible values and taskbar freshness. Local Release build: zero warnings/errors. All 61 Python tests, three browser tests and 740 native layout cases passed, including the new selection regressions. Synthetic expanded and ribbon renders were inspected. Hosted results, exact package verification and release checksum are recorded with the patch release. The README documents the Cursor-specific summary semantics.

## 2.1.0 provider ecosystem — 2026-10-04

Reviewed main at 2f8b1f3 before changes. Confirmed and fixed two existing rendering regressions: any extra hardware selection forced compact mode, and omitted-count taskbar previews painted their title twice. Expanded hardware now has its own grid; insufficient space uses compact mode without shrinking typography.

Review of the new provider pipeline found daemon-thread timeouts could leave CLI children alive after Python exited. The single-provider worker now executes synchronously and WPF owns each process tree, with a direct cancellation callback on timeout/shutdown. Native fixtures verify child termination and independent successful results. Review also found normalized empty windows hid connection/error details; that guidance is preserved and tested. Consent JSON preserves unrelated provider choices. HTTP error responses close reliably.

The provider registry is reviewed local package data, not runtime Internet code loading. All existing adapters pass the same bounded field contract; unknown metadata and obvious secret/identity patterns are dropped. OpenRouter is a separate opt-in to a documented exact HTTPS endpoint using an existing environment value; it never calls a model or fabricates account credit/reset time. Existing host/redirect restrictions remain fixed. No dependency or telemetry change.

Local validation: 61 Python tests and three browser tests passed; Release build completed with zero warnings/errors. Native verification passed 740 layout cases plus existing quota/history/forecast/update-security checks and new worker identity, timeout, shutdown-child termination, provider defaults and connection-guidance regressions. Synthetic full/ribbon and French/Hindi provider pages were visually inspected. Hidden startup, cached tray opening, duplicate-instance restoration and clean close passed. Live compatibility smoke returned current normalized Codex and Cursor results, and honest unavailable/connect states for OpenCode Go and Claude; no account values or identities were published.

Short performance observation on the same machine, real sensors and synthetic disconnected providers (four-second warmup, twelve-second samples, uncontrolled host load): 2.0 visible startup 733.0 ms, 5.33% of one CPU core, 176.93 MiB working set; 2.1 visible 733.7 ms, 5.73%, 181.17 MiB; 2.1 hidden 363.9 ms, 5.46%, 177.04 MiB. Cached tray opening took 59 ms. Settings opened in 41–95 ms, History 25–31 ms, System 23–38 ms and Providers 46–77 ms in synthetic checks. Four isolated Python workers took a median 291 ms versus 228 ms in one process across three mocked runs: approximately 63 ms extra transient startup buys independent deadlines and process-tree ownership. These are observations, not performance guarantees or live network timings. No dependency was added.

Hosted CI, final package checks, checksums and exact publication revision are recorded in the release notes after completion. Offline fixtures do not claim live-account OpenRouter acceptance. Physical hardware qualification limits from 2.0 remain. README, changelog, privacy, architecture, troubleshooting, contributor guide and the provider contract/fixture guide are updated.

## 2.0.0 system capacity — 2026-10-03

Security review found no actionable finding in the new native sensor/process/taskbar boundary: bounded PDH buffers and adapter enumeration, deterministic COM/GDI cleanup, fixed system Task Manager path, cached taskbar callbacks and no network/credential change. Bug review found two P2 defects: oversized DWM bitmaps for compact/ribbon clients and missing layout reconciliation after provider availability changed. Both were fixed with request/client-size regressions and zero→three→zero provider transitions. The old system collector also retained values after sensor failures; normalized background snapshots now age/fail to unknown. Empty metric selections are intentionally supported rather than silently restoring CPU.

Missing-counter retry adds only absent counters to the worker-owned query, preserving healthy disk-rate baselines on machines without GPU counters. Metric validation rejects non-finite/out-of-range percentages before presentation.

Local checks so far: 52 Python tests, three browser tests, zero-warning Release builds, existing 656 native layout cases plus 60 new system/empty/GPU-selection cases, prior feature/update-security/forecast checks and new sensor semantics passed. Real AMD integrated + NVIDIA discrete GPU percentage, dedicated VRAM, battery, frequency and disk counters were captured without elevation being required by the product. Initial rate samples were unknown; later samples were valid. Isolated DWM callbacks returned S_OK for thumbnail, compact Peek and ribbon Peek, including a transparent/layered window matching Prism. Synthetic French system details, Hindi consumers, taskbar bars and fourteen-metric compact/full renders were visually inspected. Final package and hosted revision checks remain publication gates, recorded by the release tag/Actions.

Performance observation from fresh isolated folders, synthetic disconnected providers, twelve-second samples after four-second warmup, uncontrolled host load: 1.9 visible 6.25% of one logical core / 184.38 MiB working set / 124.17 MiB private; 2.0 visible 5.99% / 180.67 / 119.19; 2.0 hidden 6.77% / 175.87 / 111.51. Window initialization was 1823/665/348 ms respectively and cached tray opening about 65 ms. These short samples do not establish an improvement or a hidden-mode regression; source data collection/layout costs differ and host load is uncontrolled. A pre-existing isolated 1.9 instance prevented the first benchmark launch; fresh benchmark directories resolved the instance collision without stopping another installation. Sensor worker captures typically took 21–39 ms in the native probe, off the UI thread. Live provider refresh overhead is unchanged in this release because adapters/scheduling are unchanged.

Existing metric selections, ordering, clocks, history and provider caches are preserved; new optional hardware metrics append to the ordering, and a System capacity profile enables them explicitly. No dependency, telemetry, startup write, account access or update-host change was introduced. Taskbar progress defaults to RAM but honors hidden/unknown/stale metrics and can be disabled. Windows provides one bar per taskbar button; multiple bars appear in hover/Peek or the persistent ribbon above the work-area edge. Hardware provenance/limitations are in SYSTEM-METRICS.md, architecture, privacy and troubleshooting. Physical Intel hardware, multi-monitor/DPI transitions, suspend/resume and discharging runtime remain unverified; conservative fixture behavior covers missing/future/stale data. Temperature/power/health/SMART and per-process GPU sensors are deferred.

A follow-up short sample including taskbar progress measured 1.9 visible 4.94% of one core / 177.18 MiB and 2.0 visible 6.12% / 179.58 MiB; 2.0 hidden 5.59% / 178.16 MiB. Startup observations were 400/678/374 ms and tray opening about 67 ms. Added Windows sensor/taskbar work has a measurable cost (about 1.18 percentage points of one core and 2.4 MiB in this sample), justified by the new capacity data; uncontrolled load limits precision. Hidden/full-dashboard compact tiles now skip unnecessary value/graph updates, while background snapshots, provider checks and taskbar bars remain current. Existing-user profiles also receive the optional System capacity preset without overwriting names, and confirmed desktop battery absence hides that optional metric.

Final diff review corrected dynamic metric-label translation after a language change, with a native regression check.

## Findings resolved

| Severity | Location | Finding and resolution |
| --- | --- | --- |
| P2 | auto_sources.py, cached account reads | A recent cache could retain an expired quota window or hide a failed refresh. Filter expired windows before every cached return and preserve stale/error status during backoff. Regression tests added. |
| P2 | claude_cli.py, login | API-key authentication could skip the subscription login required by the reader. Reuse the subscription-auth predicate in setup and collection; verify after login. Regression tests added. |
| Hardening | claude_feed.py | Rebuild only known numeric quota fields instead of persisting arbitrary nested input. Regression tests added. |
| P2 | quota_cache.py, account and CLI caches | Malformed cache envelopes could prevent refresh indefinitely. Validate timestamps, windows and numeric fields before reuse; corrupt caches become a cache miss. |
| P2 | providers.py, fallback selection | Failed Codex telemetry and Claude CLI reads suppressed healthy alternative sources. Isolate each reader and prefer a current source over stale results. |
| Hardening | source/App.cs | Cancel collection on close and tolerate collector exit races. Repeated launches activate the existing installation window. |
| Build | Build.ps1 | Force resource rebuilding so updated embedded branding cannot be omitted by stale intermediate output. Native verification rejects stale results and nonzero exits. |
| P2 | source/App.cs, system readings | The free-disk label was paired with a used-space bar. Both compact and detailed bars now represent free space. Initial unknown sensors have neutral status. |
| P2 | source/QuotaSnapshot.cs | Validate UI quota inputs independently: keep known zero, reject invalid percentages and timestamps, filter expired windows, and fail closed for malformed mixed windows. The footer counts current sources only. |
| P2 | source/App.cs, window state | Remember the expanded height across compact launches and restore that height instead of a fixed minimum of 700 pixels. |

| Rendering | source/App.cs, app.manifest | Isolate the shadow behind content, declare PerMonitorV2 awareness, keep text opaque, and tighten compact spacing to avoid fractional downscaling. Export a 4x preview with font outlines; screen-DPI glyph caches had remained visibly pixelated in earlier exports. |

| Reminders | source/ResetReminders.cs | Require remaining capacity strictly above 10%, a future reset inside the chosen interval, and current data no older than ten minutes. Deduplicate by provider/window/reset and persist locally. |
